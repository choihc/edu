REV 3 · 2차 리뷰 반영
Design Spec · 2026-05-19

AI Native 발표 슬라이드 — 디자인 스펙

사내 개발팀 대상 20~30분 발표. 핵심 메시지는 "AI Native는 도구의 교체가 아니라 운영체계의 교체". Anthropic 1차 자료로 실증하고, 반증 데이터를 본문에서 정면 직시한 뒤 Superpowers + 멀티에이전트 운영을 사내 사례로 닫는다.
대상 사내 개발팀 분량 20~30분 · 26장 형식 React 라우트 /ai-native 디자인 Presentation.jsx(스펙매니저) 톤 계승

Executive Summary · 약 25분(±5) · 26장

① 운영체계의 교체 메시지를 5막 26장으로 누적 설득.

② 정량 데이터는 Anthropic 1차 자료로만 사용. §7.3 자료 검증 부록(2026-05-19-ai-native-sources.md)에 4필드(URL/접근일/원문/위치) 기록.

③ 슬라이드 7 신설 — 반증 데이터(-17%p 등)를 본문에서 정면 노출하고 "그래서 운영체계 재설계가 필요"로 연결.

④ 본인 팀 Superpowers + 멀티에이전트 워크플로를 Act 4(4장)에서 사례로. 슬라이드 23에서 "교훈의 일반화"로 마무리.

⑤ 데이터 모델은 8개 공통 kind + variant로 통합하여 19개 1회용 컴포넌트 제거.

5.데이터 모델 (8개 공통 kind)

19개 1회용 kind → hero · quote · stats-grid · list-rows · cards-grid · compare-rows · references · closing 의 8개 공통 kind + variant. closing은 마지막 슬라이드(Q&A) 전용으로 hero/quote와 다른 레이아웃이라 독립 kind 유지. (KIND_COUNT = 8, §1.1)

type SourceRef = { label, url?, year?, disclaimer? };

type SlideBase = {
  eyebrow?, title?, subtitle?, variant?,
  accent?: "indigo"|"pink"|"emerald"|"amber"|"violet"|"sky",
  source?: SourceRef,
  speakerNote?,
};

const slides = [
  { kind: "hero", variant: "title"|"case-intro", ... },
  { kind: "quote", quote, attribution? },
  { kind: "stats-grid", source, stats: [{value, label, delta?}] },
  { kind: "list-rows", variant, rows: [{label, body, badge?, source?}] },
  { kind: "cards-grid", variant, cards: [{title, body, accent?, icon?, link?}] },
  { kind: "compare-rows", variant, headers, rows },
  { kind: "references", groups: [{label, items: [{title, url}]}] },
  { kind: "closing", message, qaQuestions: [string] },
];
